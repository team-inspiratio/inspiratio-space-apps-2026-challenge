# S10 模型审核：前 3 名 LightGBM（E028、E018、E032）

审核人：全新上下文的审核子代理（预注册第 4 节第 5 条、计划第 5 节）。
脚本：`uv run python -X utf8 -m harmonization.model_review`（约 3 分钟，8 线程）。
数字都在 `reports/model-review.json`，图在 `reports/figures/s10-*.png`。
只用了两个验证窗口（main、aux）和 3 个训练区。没有碰测试数据，也没有读留出区的 VIIRS。

## 结论（先看这里）

| 实验 | 泄漏审查 | 合并 MALE | 是否阻止 S11 选它 | 主要提醒 |
|---|---|---:|---|---|
| E028 | **通过** | 0.2947 | 否 | 纬度主要起“区域标签”作用；main 零火点 Ĥ≥1 只剩 1.0 个百分点余量 |
| E018 | **通过** | 0.2950 | 否 | 同上；余量 0.7 个百分点 |
| E032 | **通过** | 0.2954 | 否 | 同上；余量 0.5 个百分点（三者最紧）；两窗口调出的参数差别最大 |

- 三个实验的代码只差特征清单，其余逐行相同。重跑分数和 `experiments.csv` 完全一致。
- 三者的分数差最多 0.0007，而对 M1s 的差的标准误约 0.015。三者实际上一样好。按规则选最低的，就是 E028。
- 没有发现泄漏：模型输入只有 `config/features.json` 的列和由它们算出的派生列；树的轮数和 Optuna 只用训练表最早的月份；predict() 只看特征表。
- **要写进 S11 和报告的风险**：纬度是允许的输入，但 3 个训练区的纬度完全不重叠，模型把纬度当成了“这是哪个区”的标签（第 5 节）。这不是泄漏，也不违反预注册，所以不阻止选择。但模型用到新区域（留出区、全球）时，效果可能明显变差。测试集 2（留出区）正好检验这一点，S11 不应为此临时改模型（那是看了验证分数再改方法）。

## 1. 泄漏检查

### 1.1 读代码的结果

| 检查项 | 结果 |
|---|---|
| 三个实验与 E028 源码的差别 | 只有 `LGB` 里的 `drop` 和 `derived` 两行（脚本用 difflib 检查） |
| 模型输入 | `lgb_inputs()` 先调用 `prepare.feature_table()`（它会拒绝 VIIRS、month、year 列），再去掉 `lat_idx`、`lon_idx` |
| 派生特征（只有 E018 用） | `modis_count = aqua_count + terra_count`，`log_aqua = log1p(aqua_count)`，都只用特征列，且单调递增 |
| 树的轮数 | 在训练表最早 24 个月上早停，再用同样轮数在整张训练表上重训 |
| Optuna | 目标是训练表最早 24 个月上的冻结判卷 MALE（加护栏罚分），参照的 M1s 也只在训练表上拟合；不看验证窗口 |
| `region` 列 | 只用于内部打分（各区 MALE 罚分）和内部 M1s，不进模型 |
| predict() | 只调用 `models_predict(feats)`，`feats` 就是判卷给的特征表 |
| 单调约束 | Aqua、Terra 火点数（及 E018 的派生计数）单调递增，保留 |

小问题（不影响结果）：配置里 `zero_rule` 写着 `cell_and_nbr`，但两段式的 `models_predict()` 并不使用它。建议在报告里说明，或以后删掉这一项，免得误读。

### 1.2 实际训练出的模型

| 实验 | 窗口 | 训练月份 | 内部留出月份 | 轮数 clf/reg（重跑 = JSON） | 特征数 | 不允许的特征 | 打乱格子编号后预测变化 |
|---|---|---|---|---|---:|---|---:|
| E028 | main | 2016-01..2021-06 | 2016-01..2018-01 | 534/592 = 534/592 | 18 | 无 | 0 |
| E028 | aux | 2018-01..2021-06 | 2018-01..2019-12 | 184/224 = 184/224 | 18 | 无 | 0 |

- main 的内部留出到 2018-01，是因为 2016–2017 年有一个月不可用（缺数据），“最早 24 个可用月”就多跨了一个月。仍然全在训练表内。
- `feature_name()` 列表：E028 = 20 个原始特征去掉两个无检测标记；E032 = 去掉两个火点天数；E018 = 全部 20 个加 `modis_count`、`log_aqua`。分类器和计数模型的列表相同。都没有 `lat_idx`、`lon_idx`、`month`、`year`、`region`、`snpp*`、`noaa20*`。

怎么看：

- 对 M1s 的差的标准误约 0.015，所以 ±0.01 以内的变化基本是噪声。
- **模型真正依赖的只有两组：纬度和 Terra 输入**。去掉任一组，MALE 变差 0.07–0.08，还过不了护栏。
- Aqua 火点数虽然重要性最高，但去掉它只差 0.010，因为 Terra 火点数、Aqua 火点天数和邻格数可以顶替。
- FRP 和日历月对 MALE 几乎没贡献，但它们帮分类器判断“有没有火”；去掉后零火点护栏不过。
- 像元面积、火点天数、邻格数、无检测标记：去掉或加回都没有实质影响。
- 依赖 Terra 是个风险：`reports/findings.md` 第 7 条说 Terra 在 2020 年后轨道漂移，训练表包含 2020–2021 年。验证窗口在 2014–2017 年，没有反映这一点。

- 分类阈值 p_fire 很稳（0.29–0.33）。叶子数、每叶最少样本也接近。

## 5. 纬度：物理效应还是区域标签？

背景：E022（E016 去掉纬度）合并 MALE 0.366，比 E016 的 0.294 差很多。3 个训练区的纬度完全不重叠：科尔多瓦 −35..−28，南部非洲 −18..−8，加州 32.5..42。所以纬度一个数就能认出是哪个区。

我做了三个测试（E028，不重训，只改验证行的纬度）：

| 测试 | 合并 MALE | 变化 | 说明 |
|---|---:|---:|---|
| 不改 | 0.2947 | — | |
| 每行纬度换成本区的中位数 | 0.3319 | +0.037 | 只保留“哪个区”，去掉区内纬度差别 |
| 三区的中位纬度轮换（加州→科尔多瓦的纬度，依此类推） | 0.5606 | +0.266 | 区内其他输入不变，只把区的身份换错；科尔多瓦 main 从 0.318 变成 0.924 |
| （对照）去掉纬度重训 | 0.3759 | +0.081 | 第 2 节 |

部分依赖曲线（`s10-pd-estimate.png` 左下）：

| 纬度带 | 平均估计的最小–最大 |
|---|---|
| 科尔多瓦（训练） | 24.4–32.8 |
| 南部非洲（训练） | 27.6–29.9 |
| 加州（训练） | 22.7–28.8 |
| 北澳大利亚（留出，−20..−10） | 27.6–29.9（与南部非洲相同） |
| 印度恒河平原（留出，24..32） | 固定 25.0（落在两个训练区之间的空白处） |
| 中西伯利亚（留出，55..65） | 固定 23.2（照搬加州北端的值） |

判断：**主要是区域识别，不是物理效应。**

1. 曲线是台阶状。跳变落在训练区的边缘，或者落在没有任何训练数据的空白纬度（例如 0° 和 −21° 附近）。物理效应（扫描几何、轨道重叠）应该是随纬度平滑变化的，而且大致只和纬度的绝对值有关。这里看不到这种规律：−32° 附近比值约 5.8，+38° 附近约 5.0，−15° 附近约 5.0。
2. 把区的身份换错，误差暴涨（+0.266）。说明模型强烈依赖“纬度 = 哪个区”。
3. 区内纬度也有用（换成中位数损失 0.037），但区内的变化是很窄的尖峰（科尔多瓦 −32° 附近、加州 38–39° 附近），更像“区内哪一条纬度带常着火”这样的地点记忆，而不是平滑的观测几何。
4. E022 去掉纬度后三个区都变差（main：加州 0.311→0.408，科尔多瓦 0.318→0.394，南部非洲 0.274→0.334），不是只差一个区。纬度给的是每个区自己的整体校准，作用类似 M1s 的“区 × 月”比值。

这对新区域意味着什么：

- 训练区以内的回推（测试集 1：训练区 2012–2013 年）应该没问题，因为区的身份不变。
- 新区域拿到的是“最近的训练区”的校准：北澳大利亚当成南部非洲（都是热带稀树草原，可能还行）；中西伯利亚当成加州北端；印度恒河平原拿到两区之间一个随意的值。这些都没有物理依据。
- 所以测试集 2（留出区）上，LightGBM 对 M1s 的优势可能缩小甚至反转。M1s 对新区域用的是三区合并的比值，至少行为可预期。
- 建议（不改变 S11 的选择规则）：S11 报告里如实写出这一点；全球阶段（G）不要把三区训练的模型直接用到远离训练纬度的地方，除非测试集 2 证明它能迁移。不要在 S11 去掉纬度，那等于看了验证分数再改方法。

## 6. 其他提醒

- main 窗口的模型在 2016–2017 年（训练表最早 24 个月）上早停和调参，这两年正好是 aux 窗口的验证期。但 aux 的分数来自 aux 自己的模型（训练 2018-01 起），所以没有泄漏。
- 零火点护栏（main，Ĥ≥1）是唯一很紧的一项：上限 0.106，E028 0.096、E018 0.099、E032 0.101。S11 用 2014-01–2021-06 重训后，这个比例可能会动。按预注册，选定只看验证集，这里只作提醒。
- 2000-11 到 2002 年年中只有 Terra、没有 Aqua。模型最依赖 Aqua 火点数，这一段怎么处理不在本审核范围，但 S12 生成序列前需要确认（M1s 也有同样问题）。
