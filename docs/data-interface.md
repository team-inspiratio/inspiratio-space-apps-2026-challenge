# Data interface spec (draft, dataset v0 / milestone A)

> For the front end. The data is in the GitHub pre-release `milestone-a` and is generated by `harmonization/series.py`. v0 is the **M1s fallback version**: it lets work on the web page start now, and S12 will produce the final version (same fields; interval fields may be added). For conventions not written here, the proposal's "What the web page delivers", "Anomaly indicators" and "From cells to user areas" apply.

## 1. Files

| File | Contents |
|---|---|
| `frontend/<region>.json.gz` | One gzip-compressed JSON per preset region (format in section 3), read directly by the web page |
| `dataset_v0.parquet` | Long table of every cell × month for the six regions (section 2), for analysis and downloads |
| `region_totals_v0.csv` | Totals by region × month × source, for quick checks |
| `SHA256SUMS.txt` | SHA256 of each file above |

Six regions: `california`, `cordoba`, `southern_africa` (training regions) and `north_australia`, `central_siberia`, `indo_gangetic` (holdout regions). Bounds are in `config/regions.json`.

## 2. Basic units and fields (`dataset_v0.parquet`)

- **Cell**: 0.25° × 0.25°. `lat_idx = floor((lat + 90) / 0.25)`, `lon_idx = floor((lon + 180) / 0.25)`, counted from the southwest corner. Cell-center latitude = −90 + (lat_idx + 0.5) × 0.25, and likewise for longitude.
- **Time**: calendar months, counted in UTC; `month` is written as `YYYY-MM`, ranging from 2000-11 to 2026-10, 312 months in total.

| Field | Type | Unit / values | Meaning |
|---|---|---|---|
| `lat_idx`, `lon_idx` | int16 | — | Cell indices |
| `region`, `role` | string | `train` / `holdout` | Region and role |
| `month` | string | `YYYY-MM` | Month |
| `est` | float32 | hotspots / cell / month (VIIRS S-NPP 375 m equivalent) | **Main value**: harmonized monthly hotspot count. Estimates may have decimals |
| `source` | category | see section 4 | Source of `est` |
| `input_complete` | bool | — | Whether the sensors used for this value were complete in that month; `false` means some days are missing and the value may be too low |
| `est_m0` | float32 | hotspots | Direct stitching (raw MODIS counts before 2012-02, S-NPP observations after), used only to show "what happens without harmonization"; null when there is no observation |
| `aqua_count`, `terra_count` | float32 | hotspots (MODIS 1 km) | Raw MODIS counts; null when the sensor was not in orbit or the whole month is missing |
| `snpp_count` | float32 | hotspots | Raw S-NPP observations (training regions only, from 2014-01); null for all holdout regions and for 2012–2013 |

**0 and null are different**: `0` means "no hotspot was recorded this month", which is not the same as certainly no fire (cloud and smoke can both cause missed detections); null means there is no data (missing or not in orbit). `est` has no nulls.

## 3. Front-end JSON (`frontend/<region>.json.gz`)

```json
{
  "version": "v0",
  "region": "california",
  "label": "California, USA (Mediterranean forest and shrubland)",
  "role": "train",
  "bbox": [-124.5, 32.5, -114.5, 42.0],
  "cell_deg": 0.25,
  "months": ["2000-11", "...", "2026-10"],
  "month_source": ["m1s_terra_bridge", "...", "snpp"],
  "month_input_complete": [true, "...", true],
  "cells": {"lat_idx": [490, "..."], "lon_idx": [222, "..."]},
  "est": [[0.0, 1.25, "..."], "..."],
  "totals": {"est": [...], "est_m0": [...], "aqua_count": [...], "terra_count": [...], "snpp_count": [...]},
  "model": {"lambda": 20.0, "m1s_fit": ["2014-01", "2021-06"], "...": "..."}
}
```

- `est[i][t]` is the estimate for the i-th cell (`cells.lat_idx[i]`, `cells.lon_idx[i]`) in the t-th month (`months[t]`), rounded to 2 decimal places.
- Within a region, **all cells have the same source in the same month**, so sources are given per month (`month_source`, `month_input_complete`).
- `totals.*[t]`: the total for the whole region in the t-th month; `null` means there is no data of that kind for that month.

## 4. Source flags (`source` / `month_source`)

| Value | Meaning | Suggested display on the web page |
|---|---|---|
| `snpp` | S-NPP VIIRS observation (training regions, complete months from 2014-01) | Observed |
| `noaa20_scaled` | S-NPP is missing or partially missing that month, so the NOAA-20 whole-month value converted to the S-NPP scale is used instead (never added to S-NPP) | Converted value; the continuity test has not yet passed human review, so **do not say "continuous" yet** (`docs/decisions/0005` item 4) |
| `m1s_aqua` | Estimate converted from Aqua MODIS with the M1s ratio | Estimate |
| `m1s_terra_bridge` | Only Terra available (2000-11 to 2002-06, and months with missing Aqua): Terra → Aqua bridge, then M1s | Low-confidence estimate |

Limitations of v0:
- This machine never has S-NPP for 2012–2013, so those two years are also `m1s_aqua` in the training regions.
- Every month in the holdout regions is an estimate (`m1s_*`).
- The Terra bridge segment in the holdout regions may be clearly too high (about 1.5–2× too high in northern Australia; see `docs/decisions/0005` item 6).
- v0 has no uncertainty intervals; S12 will add them.

## 5. From cells to the user's selected area

Add up the cells that fall inside the area; when only part of a cell is inside, apportion it by overlap area. This assumes hotspots are evenly distributed within a cell: for small selections, the boundary error can be noticeable. When the selection is smaller than one cell, give only an approximate value and point out this limitation.

## 6. Anomaly indicators (definitions; reference implementation in S14)

- **Only evaluate complete months that have ended**. While the current month is still running, show only "cumulative hotspot count as of a given date", with no anomaly verdict.
- **Anomaly multiple** = that month's `est` ÷ the historical same-month median.
- **Historical percentile**: the reference set is the years before the target year for the same calendar month that are complete and usable (`input_complete = true`); the target month itself is not included. With reference values x₁…xₙ and target h, percentile = 100 × [number less than h + 0.5 × number equal to h] ÷ n, and the number of reference years n is shown alongside.
- **Activity level**: when n ≥ 10, a percentile ≥ 90 is labeled "high", ≤ 10 "low", and anything else "normal"; when n < 10, no level is given; only the values are shown, with the note "insufficient history".
- **When the median is very small (< 5)**: show no multiple, only the percentile, with the note "few hotspots are usually recorded in this month historically".
- **Missing data**: when the target month has `input_complete = false`, show the available count and "incomplete coverage", with no level.
- **Baseline period**: from 2001 by default; alternatively, only S-NPP observed months (`source = snpp`) can be used as the baseline period. The page also shows the baseline period, data version, number of reference years and as-of date.
- **Wording**: always write "hotspot activity high / normal / low (VIIRS-equivalent estimate)", never number of fires, burned area or disaster severity.
