# Data interface spec (dataset v1 / S12 final version; v0 in section 7)

> For the front end. v1 is in the GitHub full Release `v1` (CC BY 4.0; the earlier pre-release `dataset-v1` has the same data) and is generated by `uv run python -X utf8 -m harmonization.series_v1 build`. v1 uses the selected model **LightGBM E028** (frozen in S11 and scored by the external blind grading); its fields are compatible with v0, with intervals and a near real-time flag added, and the source names change from `m1s_*` to `model_*`. For conventions not written here, the proposal's "What the web page delivers", "Anomaly indicators" and "From cells to user areas" apply. Details of the method are in `docs/decisions/0009`.

## 1. Files

| File | Contents |
|---|---|
| `frontend/<region>.json.gz` | One gzip-compressed JSON per preset region (format in section 3), read directly by the web page |
| `dataset_v1.parquet` | Long table of every cell × month for the six regions (section 2), for analysis and downloads |
| `dataset_v1.csv.gz` | The same table as CSV (gzip-compressed, UTF-8, LF line endings): an empty field = no data, numbers kept to 6 significant digits, booleans written as `True`/`False` (S14) |
| `data-card.md` | Data card (sources, processing, uncertainty, validation, limitations, citation; in English, with a short summary at the end) |
| `anomaly-cases.json` | Standard test cases for the anomaly indicator (section 6), for the front end to check its answers one by one |
| `region_totals_v1.csv` | Totals, intervals, sources and flags by region × month |
| `resamples20_v1.parquet` | Cell-level estimates from the first 20 resamples (non-zero values only; columns `lat_idx, lon_idx, month, resample, value`), for computing intervals over areas the user draws: sum each `resample` separately, then take the values near the 2nd smallest and the 19th largest as approximate 5%/95% |
| `meta.json` | Model, training range, numbers of trees, whether the intervals are calibrated |
| `SHA256SUMS.txt` | SHA256 of each file above |

Six regions: `california`, `cordoba`, `southern_africa` (training regions) and `north_australia`, `central_siberia`, `indo_gangetic` (holdout regions). Bounds are in `config/regions.json`.

## 2. Basic units and fields (`dataset_v1.parquet`)

- **Cell**: 0.25° × 0.25°. `lat_idx = floor((lat + 90) / 0.25)`, `lon_idx = floor((lon + 180) / 0.25)`, counted from the southwest corner. Cell-center latitude = −90 + (lat_idx + 0.5) × 0.25, and likewise for longitude.
- **Time**: calendar months, counted in UTC; `month` is written as `YYYY-MM`, ranging from 2000-11 to 2026-10, 312 months in total.

| Field | Type | Unit / values | Meaning |
|---|---|---|---|
| `lat_idx`, `lon_idx` | int16 | — | Cell indices |
| `region`, `role` | string | `train` / `holdout` | Region and role |
| `month` | string | `YYYY-MM` | Month |
| `est` | float32 | hotspots / cell / month (VIIRS S-NPP 375 m equivalent) | **Main value**: harmonized monthly hotspot count. Estimates may have decimals |
| `lo_90`, `hi_90` | float32 | hotspots | Cell-level stability interval (5%/95% quantiles of 100 whole-year resamples); it reflects only "how much the estimate would change with a different set of training years" and is not an error range. Equal to `est` for observed months and NOAA-20 months |
| `source` | category | see section 4 | Source of `est` |
| `nrt` | bool | — | This value comes from near real-time data (VIIRS from 2026-08, MODIS from 2026-09) and will be revised slightly once the standard products are released |
| `input_complete` | bool | — | Whether the sensors used for this value were complete in that month; `false` means some days are missing and the value may be too low |
| `est_m0` | float32 | hotspots | Direct stitching (raw MODIS counts before 2012-02, S-NPP observations after), used only to show "what happens without harmonization"; null when there is no observation |
| `aqua_count`, `terra_count` | float32 | hotspots (MODIS 1 km) | Raw MODIS counts; null when the sensor was not in orbit or the whole month is missing |
| `snpp_count` | float32 | hotspots | Raw S-NPP observations (training regions only, from 2014-01); null for all holdout regions and for 2012–2013 |

**0 and null are different**: `0` means "no hotspot was recorded this month", which is not the same as certainly no fire (cloud and smoke can both cause missed detections); null means there is no data (missing or not in orbit). `est` has no nulls.

## 3. Front-end JSON (`frontend/<region>.json.gz`)

```json
{
  "version": "v1",
  "region": "california",
  "label": "California, USA (Mediterranean forest and shrubland)",
  "role": "train",
  "bbox": [-124.5, 32.5, -114.5, 42.0],
  "cell_deg": 0.25,
  "months": ["2000-11", "...", "2026-10"],
  "month_source": ["model_terra_bridge", "...", "snpp"],
  "month_nrt": [false, "...", true],
  "month_input_complete": [true, "...", true],
  "cells": {"lat_idx": [490, "..."], "lon_idx": [222, "..."]},
  "est": [[0.0, 1.25, "..."], "..."],
  "totals": {"est": [...], "lo_90": [...], "hi_90": [...], "est_m0": [...], "aqua_count": [...], "terra_count": [...], "snpp_count": [...]},
  "model": {"model": "LightGBM E028 ...", "training": {"months": ["2014-01", "2021-06"]}, "interval": {"calibrated": true, "...": "..."}}
}
```

- `est[i][t]` is the estimate for the i-th cell (`cells.lat_idx[i]`, `cells.lon_idx[i]`) in the t-th month (`months[t]`), rounded to 2 decimal places.
- Within a region, **all cells have the same source in the same month**, so sources are given per month (`month_source`, `month_input_complete`).
- `totals.*[t]`: the total for the whole region in the t-th month; `null` means there is no data of that kind for that month.
- `totals.lo_90/hi_90`: the stability interval of the regional total (first sum each resample into a regional total, then take 5%/95%). When `model.interval.calibrated = true`, it has been widened around the estimate by the factor set on the validation set (`docs/decisions/0008` section 5), and its coverage has been tested on the test set (`reports/final-test.md`).

## 4. Source flags (`source` / `month_source`)

| Value | Meaning | Suggested display on the web page |
|---|---|---|
| `snpp` | S-NPP VIIRS observation (training regions, complete months from 2014-01) | Observed |
| `noaa20_scaled` | S-NPP is missing or partially missing that month, so the NOAA-20 whole-month value converted to the S-NPP scale is used instead (never added to S-NPP) | Converted value; the continuity test has not yet passed human review, so **do not say "continuous" yet** (`docs/decisions/0005` item 4) |
| `model_aqua` | Estimate computed by the selected model from MODIS (Aqua + Terra) inputs | Estimate |
| `model_terra_bridge` | Aqua incomplete, only Terra available (2000-11 to 2002-09, and months with missing Aqua): Aqua inputs are built from Terra before going into the model | Low-confidence estimate (on the validation set the error is about 1.6 times that with Aqua) |

Limitations of v1:
- This machine never has S-NPP for 2012–2013 (test-set isolation), so those two years are also `model_aqua` in the training regions (`docs/decisions/0009` item 1).
- Every month in the holdout regions is an estimate (`model_*`), with bridge ratios fitted on local MODIS.
- The model's latitude input in practice acts as "which training region this resembles"; whether it can be used far from the training regions should be decided from the Test 2 scores (`reports/model-review.md` section 5, `reports/final-test.md`).
- The continuity criterion for the NOAA-20 segment has not yet been confirmed by a person, so do not say "continuous" yet.

## 5. From cells to the user's selected area

Add up the cells that fall inside the area; when only part of a cell is inside, apportion it by overlap area. This assumes hotspots are evenly distributed within a cell: for small selections, the boundary error can be noticeable. When the selection is smaller than one cell, give only an approximate value and point out this limitation.

## 6. Anomaly indicators (reference implementation `harmonization/anomaly.py`, standard test cases `anomaly-cases.json`)

The front end implements the same function `anomaly(series, target, as_of, baseline)` following the rules below, then feeds the `input` of each case in `anomaly-cases.json` into it and compares every field with `expected` (numbers within a relative error of 1e-9, lists exactly equal). 25 cases: 19 hand-worked edge cases (ties, exactly 90/10, 9 reference years, a median of 0, a target month with missing data, an unfinished current month, the S-NPP baseline period and so on) and 6 examples using real regional totals from dataset v1. Output fields: `status`, `value`, `n_ref`, `ref_years`, `median`, `ratio`, `percentile`, `level` (`high`/`normal`/`low`/null), `preliminary`, `notes`. The Chinese and English wording is also in `labels` and `notes` in the JSON. The original definitions below are unchanged; S14 added a few details (`docs/decisions/0011`):

- **End of month**: a month counts as ended only if the as-of date (UTC, `YYYY-MM-DD`) is no earlier than the 1st of the next month.
- **Ties**: values are given only to 2 decimal places, so |x − h| ≤ 0.005 counts as "equal" and x < h − 0.005 as "less".
- **Reference set**: the same calendar month, from 2001 to the year before the target year, with a value and `input_complete = true`; when the "S-NPP" baseline period is chosen, only months with `source = snpp` are kept. Terra-only months (low confidence) also count as references.
- **Order of statuses**: no value `no_data` → current month not yet over `month_in_progress` (show only the value so far) → target month with missing data `incomplete_coverage` → no reference months `no_history` → 1–9 reference years `insufficient_history` (give the percentile, median and multiple, but no level) → `ok`.
- Median = the ordinary median (the mean of the middle two when the count is even); when the median is < 5, no multiple is given and `small_median` is added to `notes`; when the target value comes from near real-time data, `preliminary = true`.

Original definitions:

- **Only evaluate complete months that have ended**. While the current month is still running, show only "cumulative hotspot count as of a given date", with no anomaly verdict.
- **Anomaly multiple** = that month's `est` ÷ the historical same-month median.
- **Historical percentile**: the reference set is the years before the target year for the same calendar month that are complete and usable (`input_complete = true`); the target month itself is not included. With reference values x₁…xₙ and target h, percentile = 100 × [number less than h + 0.5 × number equal to h] ÷ n, and the number of reference years n is shown alongside.
- **Activity level**: when n ≥ 10, a percentile ≥ 90 is labeled "high", ≤ 10 "low", and anything else "normal"; when n < 10, no level is given; only the values are shown, with the note "insufficient history".
- **When the median is very small (< 5)**: show no multiple, only the percentile, with the note "few hotspots are usually recorded in this month historically".
- **Missing data**: when the target month has `input_complete = false`, show the available count and "incomplete coverage", with no level.
- **Baseline period**: from 2001 by default; alternatively, only S-NPP observed months (`source = snpp`) can be used as the baseline period. The page also shows the baseline period, data version, number of reference years and as-of date.
- **Wording**: always write "hotspot activity high / normal / low (VIIRS-equivalent estimate)", never number of fires, burned area or disaster severity.
