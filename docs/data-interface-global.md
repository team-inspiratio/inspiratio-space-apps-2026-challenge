# Data interface spec: global version (global-v1, stage G)

> For the front end. The global version is in GitHub Release `global-v1` (CC BY 4.0) and is generated by `uv run python -X utf8 pipeline.py global` (the individual steps are in `harmonization/series_global.py`). The fields, JSON format, source flags and anomaly indicator rules are **exactly the same as v1** (sections 2–6 of `docs/data-interface.md`); this document covers only the differences. Details of the method are in `docs/decisions/0013`.

## 1. How it differs from v1

- **Coverage**: 278,192 global 0.25° cells × 312 months (2000-11 to 2026-10), 86.8 million cell-months in total. Inclusion rule: GFED land cells, cells that have ever had a hotspot, and cells in the scoring rectangles and in v1's six boxes (`config/regions-global.json`). Cells outside this coverage (mainly open ocean) are all treated as 0.
- **Regions**: the 14 GFED4.1s basis regions (`region` field: `BONA`, `TENA`, `CEAM`, `NHSA`, `SHSA`, `EURO`, `MIDE`, `NHAF`, `SHAF`, `BOAS`, `CEAS`, `SEAS`, `EQAS`, `AUST`). The three holdout regions (`north_australia`, `central_siberia`, `indo_gangetic`) are **listed separately** and not counted in the GFED region they lie in. New field `gfed_region`: the GFED region each cell lies in, holdout-region cells included.
- **Model**: still E028, with frozen parameters and numbers of trees, but retrained on the global training cells (2014-01 to 2021-06, excluding the holdout regions). So it is **not** the model that took the test. The S11 test scores belong to the version trained on the 3 demo regions only; the global version has only validation-window scores (`reports/global-scores.md`).
- **Intervals**: use the **first 50** of the year-block resamples sealed in S11 (v1 uses 100). This is an approximation to save run time, and the quantiles are slightly noisier (ADR 0013 item 5 addendum). The widening factor for regional-total intervals is re-derived with the same formula on the global validation windows, again with 50 resamples each:
  - The result is **16.75** (v1: 5.37).
  - Without widening, only 14% of the true region × month values on the validation windows fall inside the interval; after widening, 90%.
  - So the global version's regional intervals are much wider than v1's. For region × month intervals in modeled years, the median width is 0.5–1.6 times the estimate, widest in the boreal forests, the Middle East, Europe and the holdout regions. About 19% of modeled region × month intervals have a lower bound of 0.
  - The values are in `interval` in `meta.json`.
- **Sources**: every non-holdout cell is a "training cell", and complete months from 2014-01 on are S-NPP observations (`source = snpp`). Every month in the holdout regions is a model estimate.

## 2. Files

| File | Contents |
|---|---|
| `frontend/index.json` | Front-end file list: for each region or box, `name`, `label`, `role`, `bbox`, `kind` (`region` / `box`), `file`, `cells` |
| `frontend/<name>.json.gz` | One per region, in exactly the same format as v1 section 3. The 14 GFED regions and the 3 holdout regions (`kind = region`); plus v1's 3 training boxes `california`, `cordoba`, `southern_africa` (`kind = box`, cut out of the global results; the values come from the global model and differ from v1). A GFED region's `bbox` is the bounding rectangle of its cells; the region's actual shape is given by `cells` |
| `dataset_global-v1.parquet` | Long table of every cell × month: the fields of v1 section 2, plus `gfed_region` |
| `dataset_global-v1.csv.gz` | The same table as CSV (same rules as v1) |
| `region_totals_global-v1.csv` | Totals, intervals, sources and flags by region × month (14 GFED regions + 3 holdout regions) |
| `box_totals_global-v1.csv` | Totals and intervals for v1's six boxes × month (computed with the global model) |
| `resamples20_global-v1.parquet` | Cell-level non-zero estimates from the first 20 resamples (same columns as v1), for approximate intervals over areas the user draws |
| `meta.json` | Model, training range, numbers of trees, interval factor, acceptance results |
| `data-interface-global.md`, `data-card.md`, `anomaly-cases.json` | This document, the data card, the anomaly indicator test cases (same as v1) |
| `SHA256SUMS.txt` | SHA256 of each file |

Sizes: Parquet about 201 MB, CSV.gz about 398 MB, `resamples20` about 663 MB, front-end JSON about 32 MB in total (compressed).

## 3. How the front end uses it

- First read `frontend/index.json` to list the selectable regions, then load a single region's `.json.gz` on demand. Each file is 0.1–5 MB compressed and up to about 57 MB uncompressed (BOAS, 44,958 cells). Load on demand; do not read everything at once.
- For the overview on a world map, use `region_totals_global-v1.csv` (region × month, very small).
- The anomaly indicator rules and test cases are unchanged (v1 section 6).

## 4. Confidence (must be shown on the web page)

- **Global validation scores** (`reports/global-scores.md`, MALE averaged over the two validation windows, lower is better):
  - All scoring rectangles: global E028 0.534, M1s 0.619.
  - In 4 regions M1s is better: CEAM, EQAS, NHSA, SHSA.
  - The boreal forests are worst: BOAS about 1.03, BONA about 0.65. Consistent with Test 2 (central Siberia MALE 1.14).
  - Suggest that the web page marks BOAS, BONA, MIDE and the holdout regions as "low confidence".
- **2012-02 to 2013-12**: model estimates globally as well (this machine never has S-NPP for these two years, red line 1).
- **Terra-only months** (`model_terra_bridge`) remain low confidence.
- The estimates express only "hotspot counts on the VIIRS S-NPP scale", not numbers of fires or burned area.
