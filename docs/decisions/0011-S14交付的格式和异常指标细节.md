## 1. 异常指标：补上的细节（`harmonization/anomaly.py`）

| 问题 | 定下的做法 | 理由 |
|---|---|---|
| 当月什么时候算结束 | 截至日期（UTC）不早于下个月 1 日 | 和“按 UTC 统计自然月”一致 |
| 浮点数怎么判断“相等” | \|x − h\| ≤ 0.005 算相等，x < h − 0.005 算更小 | 前端 JSON 只给 2 位小数，用户自圈区域是很多格子相加，JS 和 Python 的加法末位可能不同；容差避免同一个数被判成两种结果 |
| 参考集里要不要 Terra 桥接月份 | 要（只要 `input_complete = true`） | 规则只排除缺测年份；桥接月份在数据里已标低置信度 |
| 基准期“只用 S-NPP” | 只留 `source = snpp` 的月份 | 提案原话是“只用 S-NPP 完整月份”；训练区 2012–2013 在 v1 是模型估计，不算 |
| 中位数为 0 | 不算倍数（< 5 都不算），百分位照常 | 避免除以 0；提案要求中位数小时只显示百分位 |
| 输出格式 | 固定 10 个字段和 6 种状态（见 `docs/data-interface.md` 第 6 节） | 前端可以逐字段对答案 |

- **标准测试用例** `docs/anomaly-cases.json`：19 个人工推算期望值的边界情况（期望值写在代码里，是手算的，不是跑程序得到的），加 6 个用数据集 v1 真实区域总量的例子（期望值是参考实现的输出，用来锁住真实数据上的行为）。`tests/test_anomaly.py` 检查参考实现能对上全部用例，而且文件里的手算用例和代码一致。
- **需要前端确认**：这些细节前端也要照做。如果前端已经按别的方式做了，以本记录为准，或者由人决定改哪边。

## 2. CSV 格式（`dataset_v1.csv.gz`）

- 和 Parquet 同一张表、同样的列顺序；gzip 压缩（约 18 MB，未压缩约 260 MB）；UTF-8、LF 换行；gzip 时间戳固定为 0，同样的输入在任何机器上得到相同的字节。
- 空字段 = 没有数据（和 Parquet 的空值一致）；数值保留 6 位有效数字（和 Parquet 的 float32 相比相对误差小于 5 × 10⁻⁶，已逐列核对）；布尔值写 `True`/`False`。
- 生成：`uv run python -X utf8 -m harmonization.series_v1 package`（只从现有 Parquet 生成 CSV、复制文档、重算 SHA256，不重训模型）；`build` 也会顺带做这一步。
