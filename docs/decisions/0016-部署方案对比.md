## 背景

评委要能打开网站，而且一直打得开。官方日程里，比赛是 2026-11-14 至 15 日，之后评审，12 月公布 Global Nominees 等名单，2027 年 1 月公布 Global Winners（[Participant FAQs](https://www.spaceappschallenge.org/resources/participant-faqs/)）。所以**网站至少要稳定运行到 2027 年 1 月**，不是只撑过比赛周末。

## 操作步骤

### A 继续用 chatgpt.site

1. PR #4、#5 合并后，由有 Sites 权限的人按 `web/README.md` “现有部署和重新部署方法”发布。
2. 用无痕窗口确认首页、`/methods.html`、数据文件都能打开。
3. 确认访问范围，并更新 README。

### B Vercel（CLI 上传产物）

1. 一名队员注册账号，确认组织项目是否符合 Hobby 条款。
2. 本地 `npm ci`、`npm run data:prepare`、`npm test`、`npm run build`。
3. 用 Vercel CLI 上传 `web/dist`，确认生产地址。
4. 确认部署保留策略，不会在评审期被清理。

### C Netlify（手动上传产物）

1. 一名队员注册，确认新项目已发布为公开（新项目默认私有）。
2. 同 B 第 2 步，上传 `web/dist`。
3. 打开用量提醒，估算评审期流量。

### D GitHub Pages

1. 人决定把仓库改公开（X2），先过一遍历史和 Release 内容。
2. 处理路径，二选一：
   - 改代码：Vite 配 `base`，把 14 处根路径改成相对路径，开 PR 走测试；
   - 不改代码：新建公开仓库 `team-inspiratio.github.io`，只放构建产物，网站就在根路径。这样源码仓库的公开与否和部署分开。
3. 新增工作流：`npm ci` → `data:prepare`（Release 用 `GITHUB_TOKEN` 下载）→ `npm test` → `npm run build` → 发布到 Pages。
4. 仓库 Settings → Pages 选 GitHub Actions。这一步要管理员操作。
5. 无痕窗口验收。

## 建议

**分两步，别在比赛周末搬家：**

1. **现在（11/13 之前）**：合并 #4、#5 后，先用 **A** 重新发布。它不用改代码，马上能把修复版放上线，也是不管后面怎么选都不白做的一步。
2. **X2 决定公开后**：改用 **D** 作为评委链接，A 留作备用。理由：
   - 评审要持续到 2027 年 1 月，D 不依赖某一个人的账号，也不会因额度用完而停；
   - 任何管理员都能修，发布过程全队可见；
   - 免费，而且容量最宽裕；
   - 比赛条款本来就倾向公开，公开之后 D 没有额外代价。

**如果决定不公开**：继续用 A，并确认它能保留到 2027 年 1 月。B、C 都有“单人账号”和“额度或条款”的风险，只当临时备用。

**提交给评委前**：不管选哪个，都用无痕窗口和一台没登录过的手机测一遍，把链接写进 `docs/submission/checklist.md`。
