# 0014 提案：考试结束后，用 2012–2013 年 S-NPP 观测值替换训练区的估计值

> **这是提案，没有实现。** 本记录不下载任何数据，不改任何护栏、冻结文件或数据集。做不做由人决定。

## 背景

计划本来要在训练区 2012-02 至 2026-10 使用 S-NPP 观测，但红线 1 规定本机永远不下载 2012、2013 年的 S-NPP，因为它们是最终测试的答案。所以数据集 v1 里这段时间是模型估计（ADR 0009 第 1 条），那条记录也写了另一种做法：考完后由人解锁，换成观测。

现在测试已经结束：

- 标签 `final-test` 由人推送，只运行了一次（[运行记录](https://github.com/team-inspiratio/inspiratio-space-apps-2026/actions/runs/41768696897)）。
- 成绩在 `results/final-test/`，结果提交 `742547e`，2026-11-04 03:50 UTC。

涉及的范围：

- **月份**：2012-02 至 2013-12，共 23 个月。阅卷时其中 22 个月可用（2012 年 10 个月、2013 年 12 个月，ADR 0010 第 2 条），不可用的那个月仍保留模型估计。
- **格子**：3 个训练区 3,904 个格子，共 89,792 个格子-月份（等于答卷里测试 1 的行数）。
- **不在范围内**：留出区的 VIIRS 继续锁住，本提案不解锁。

这么做的好处：

- 训练区 2012 年以后的序列全部变成观测，日历上的“观测 / 估计”分界线从 2014-01 提前到 2012-02。
- 直接拼接视图不再有 2012–2013 的空白，2012 年的假台阶可以直接看到。
- “只用 S-NPP” 的异常基准多两年历史。

## 为什么不影响已报告的测试成绩

| 成绩依赖什么 | 替换后会不会变 |
|---|---|
| 封存的答卷 `results/submission.parquet`（冻结，哈希在 `config/frozen-manifest.json`） | 不变。替换的是新版本数据集，不是答卷 |
| 阅卷结果 `results/final-test/`（由云端生成，已提交） | 不变，也不重算 |
| 冻结模型 `results/freeze.json` 和 `harmonization/harmonize.py` | 不变。**选项 B 不重训** |
| 阅卷工作流 `grader.yml` | 不变。它发现已有成绩就拒绝运行，所以不可能考第二次 |
| 已发布的 Release `v1` | 不变。新数据用新版本号发布，v1 保持原样 |

逻辑上也成立：成绩回答的是“模型只看 MODIS 时，能不能估出这两年的 VIIRS”。这个问题在 2026-11-04 已经回答完。之后把估计值换成观测值，只改变数据产品里这些格子显示什么，不改变模型当时交的答卷。

**有三个边界必须说清楚：**

1. **只有不重训才成立。** 如果把这两年并进训练（选项 C），上线模型就不再是考过试的模型，“成绩就是上线版的成绩”这句话作废（ADR 0009 第 1 条的好处就没了）。
2. **这两年以后不能再当测试集。** 将来要证明改进后的模型，必须用没碰过的新数据（`docs/project-journey.md` 第 6 节也这么写）。
3. **“答案从未到过本机”要加时间限定。** 解锁后要改成“在测试结束之前，答案从未到过本机”，并写明解锁日期。相关文字在 `docs/ai-usage.md`、`reports/validation.md`、`docs/data-card.md` 和网页方法页。

## 选项

| 选项 | 做法 | 好处 | 坏处 |
|---|---|---|---|
| A 保持现状 | 不解锁，继续用估计值（ADR 0009 的推荐） | 零风险，所有文字都不用改 | 空白和“估计值”一直存在 |
| **B 只替换数值，不重训** | 解锁后把可用月份换成观测，发新版本 | 成绩不受影响；产品更完整 | 要改护栏和不少文字；这两年不再能当测试集 |
| C 替换并重训 | 把这两年并进训练，再生成序列 | 接近原计划，训练数据多 23 个月 | 上线模型没有测试成绩，等于放弃盲审这一核心证据 |

选 B 时，数据怎么拿到有两种做法：

| 做法 | 过程 | 要改的护栏 |
|---|---|---|
| **U1 云端汇总** | 新建一次性工作流，在 GitHub 云端下载年度包，用冻结的清洗和网格化代码算出训练区“格子 × 月份”计数，作为 Release 附件；本机只下载这份汇总 | 较少，本机的下载锁可以保留 |
| U2 本机下载 | 改掉本机的锁，直接下载年度包走完整流程 | 较多，而且年度包含全球数据，要确保留出区在导入时丢弃 |

## 怎么验收（实施时）

1. 云端下载的 2012、2013 年度包 SHA256 必须和 `results/final-test/locked-data-sha256.txt` 一致。不一致就停下问人。
2. 新数据里各训练区每年的观测总量，要等于阅卷记录的总量（`results/final-test/scores.json` 的 `total_bias` 里的 `V`，例如加州 2012 年 42,767，只算阅卷可用的月份）。
3. `results/final-test/`、`results/submission.parquet`、Release `v1` 一个字节都不变。
4. `tools/guardrails.py check` 和 `pipeline.py check` 通过。

## 建议

**选 B + U1**：只替换数值，不重训，用云端汇总。理由：

- 成绩完全不受影响，还能用阅卷记录反过来核对新数据。
- 本机的下载锁可以保留，改动最小。
- 盲审是这个项目最硬的证据，不值得为了多 23 个月训练数据（选项 C）放弃。

**时间上**：如果比赛前来不及，提交版保持现状（选项 A）完全没有问题，现状是诚实的，文档也都写清楚了。不要为了赶时间在比赛前一两天改红线。
