## 2. 结果一览

- **盲审（只考一次）**：E028 在测试 1（训练区 2012–2013 年）上比 M1s 误差低 22%，在测试 2（没见过的留出区）上低 25%。但留出区的误差是训练区的 2.5 倍，总量偏低（[`reports/final-test.md`](../reports/final-test.md)）。
- **全球验证**：用全球数据重训后，MALE 0.534，M1s 是 0.619，低 14%；14 个 GFED 区赢了 10 个（[`reports/global-scores.md`](../reports/global-scores.md)）。
- **无断层**：全球 2013 年（模型）1,600 万个火点，2014 年（观测）1,660 万个（[`reports/global-review.md`](../reports/global-review.md)）。
- **可复现**：全新克隆，`pipeline.py all` 一条命令，37 项核对逐位一致（ADR 0012）。

## 3. 关键决定和理由

1. **预注册 + 冻结 + 外部盲审只考一次**：2012–2013 年的 S-NPP 数据本机永远不下载，只有 GitHub Actions 能下载并打分。目的是不让“看了答案再改模型”的事发生。代价是考完就不能再用这块数据证明改进；好处是成绩站得住，这是我们比大多数参赛作品硬的地方。
2. **两段式（hurdle）LightGBM**：大部分格子-月份是 0 火点。普通回归会在没火的地方估出零星的小数，被“零火点护栏”卡住：真值为 0 的矩形里，估计值 ≥ 1 的比例最多只能比 M1s 高 5 个百分点。所以先判断“有没有火”，再估“有多少”（ADR 0007、0008）。
3. **S10 缩减预算**：Optuna 从 30 次试验降到 15 次，两个实验并行，设截止时间，最接近过关的两个候选（E016、E021）再用 30 次复跑，用复跑的分数参与选择。理由是时间有限，规则在看到结果之前就定好了（ADR 0007）。
4. **固定 8 线程，不用 GPU**：
   - LightGBM 的结果和线程数有关，固定线程才能逐位复现。
   - pip 版 LightGBM 没有 GPU 支持；GPU 的浮点顺序也不同，会破坏逐位复现。
   - 当时数据量（几百万行）用 GPU 也快不了多少。
5. **全球版用全球数据重训**：只用 3 个示范区训练的模型，在没见过的地方会低估。全球重训后，全球验证分数从 0.563 降到 0.534。代价是全球版的模型不是考过盲审的那一个，这一点在接口文档里写明了（ADR 0013 第 3 条）。
6. **全球区间只用 50 次重抽**：原计划 100 次，内存只够一次跑一个进程（每个进程启动时峰值 17–21 GB，机器 31 GB）。用的是 S11 封存抽样的前 50 次，仍可逐位复现（ADR 0013 第 5 条补充）。
7. **区间放大系数重新求**：重抽区间只反映“换一批训练年份会差多少”，太窄。在验证窗口上校准到真正盖住 90%：示范区是 5.37，全球是 16.75。

## 4. 已知弱点（报告里如实写了）

- **没见过的地方偏低**：留出区误差是训练区的 2.5 倍，总量偏低 20–35%。全球重训后有改善，但北方森林（BOAS、BONA）仍然最差。
- **热带森林区不如基线**：中美洲、南美南北两部分、赤道亚洲比 M1s 差 3–14%。可能因为这些地方的火主要是砍伐雨林烧荒，和草原火的规律不同。
- **区域年度总量偏差**：全球版平均偏 10%，M1s 是 5–7%。单个格子更准，加总后有偏。
- **零星假火点**：真值为 0 的地方，估计值 ≥ 1 的比例是 4.9%，M1s 是 1.7%。在护栏允许范围内。
- **区间很宽**：全球版区间典型宽度是估计值的 0.5–1.6 倍。网页上只能叫“大致范围”。

## 5. 回头看：能做得更好的地方

- **计划是 AI 写的初稿，不是规定。** 应该在冻结前主动问一句“有没有更快或更好的做法”。例如区间可以用**共形预测**（直接用验证误差，不用重训）或**分位数回归**（多训练 2 次），几分钟就能算完，不用重训几百次。冻结前提出来几乎没有代价，冻结后就只能等。
- **全球阶段卡在内存，不在 CPU。** 31 GB 内存只够一次跑一个全球重抽进程。下一次在 64 GB 以上的机器上跑，或者分块读表降低峰值，比换 CPU 或 GPU 更有用。
- **数据量到千万行后，GPU 才值得。** 要用的话，先花一次时间编译 CUDA 版 LightGBM，并接受“容差内一致”而不是“逐位一致”，写进决定记录。

## 6. v2 或写论文还缺什么

现在的成果是一份扎实的工程原型：预注册、盲审、可复现，这些已经超过很多同领域论文。要发论文还要补：

| 缺什么 | 怎么补 |
|---|---|
| 和前人比 | 文献调研；和已有的 MODIS/VIIRS 协调方法、FireCCI、GFED 产品正面对比 |
| 新意 | 论证“预注册、盲审的跨传感器协调流程”这个点，请懂行的老师判断够不够 |
| 独立验证 | Landsat 或 Sentinel 的燃烧面积、地面记录 |
| 消融实验 | 逐个去掉特征、换模型，看效果变化 |
| 解释原因 | 加土地覆盖等特征，分析热带区和北方森林为什么差 |
| 重新盲审 | 改进模型（土地覆盖特征、区域总量校准、更高的“有火”门槛、共形区间）后，留一块**没碰过的新数据**再考一次 |

粗略估计：AI 能做的部分是 1–2 周（含机器运行时间），审稿周期 3–9 个月。
