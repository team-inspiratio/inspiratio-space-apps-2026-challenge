## 3. 验证（按论文标准；指标和门槛在动手前写进预注册）

1. **主指标照提案**：随机矩形上的 MALE。每个 GFED 区约 150 个矩形，每个示范区另加 200 个。先按区和完整年份分别求均值，再等权汇总。辅助指标：零火点上的正估计比例、1–9 个火点的误差、总量偏差、季节相关。
2. **比较要有置信区间**：LightGBM 与 M1s、QM 的分数差，用"年份 × 区域"块状重采样给出 95% 区间。重叠的矩形不算独立样本，不报 p 值。
3. **按用途验证**（新增，最贴近题目）：在测试年份里，用"协调后历史"和"真实 VIIRS 历史"分别算出最近月份的"偏高 / 正常 / 偏低"，看两者有多一致（Cohen's κ）。直接回答"用我们的数据做异常判断靠不靠谱"。
4. **独立参照的合理性检查**（ESSD 要求）：用 GFED 燃烧面积看"火点数 ÷ 燃烧面积"在 2012 年前后是否平稳；与文献数值对照（例如热带 VIIRS 比 MODIS 多约 70%）。这只是合理性检查，不用来调模型。
5. **不确定性要被检验**（Merchant 2017）：必做的是年份块重采样得到稳定性区间，并在测试集上**报告实际覆盖率**。如果覆盖不足，就用验证集残差校准区域汇总的区间，在测试集上报告校准后的覆盖率。
6. **年代偏移调查（提案 D1 必做）**：用分类器区分 2002–2011 年和 2014–2021 年的输入特征，并分析原因。
7. **选定规则照提案**：比 M1s 至少好 10%，两个窗口都不能明显退步，护栏指标在容差内，并通过泄漏审查；否则用 M1s。另加防刷分规则：改进要超过 1 个标准误才算数。

## 4. 测试集隔离：外部盲审阅卷

1. **时间锁在物理上不存在于本机**：本机**永远不下载** 2012 年和 2013 年的 S-NPP 数据。
2. **空间锁只在导入时经过一次，不落地**：留出区的 VIIRS 记录在流式导入时直接丢弃，不写入磁盘；导入完成后删除原始 VIIRS 压缩包，只保留哈希。
3. **AI 本身受钩子限制**：项目 `.claude/settings.json` 配置 PreToolUse 钩子，拦截两类操作：
   - 任何请求锁住年份或地区 VIIRS 的下载命令或网址；
   - AI 实验阶段对 `prepare`、`evaluate`、`grader` 等固定文件的修改。
4. **阅卷人是 GitHub Actions，不是我**：
   - 阅卷工作流 `grader.yml` 在**建模开始前**就提交，并写进预注册；
   - 冻结模型后，本机只用 MODIS 输入生成测试期的预测 `submission.parquet`，把它的哈希写进冻结清单并 commit（先封存答卷）；
   - 推送 `final-test` 标签后，GitHub 的云端机器**自己从 FIRMS 下载**被锁住的 VIIRS 数据，用同一个 commit 的代码算出标准答案、打分，再把结果提交回仓库；
   - 工作流发现已经有结果就拒绝再跑，**只能考一次**。
5. **结论**：本机和 AI 从来没有拿到过测试答案，成绩由第三方环境算出，全过程留有时间戳。剩余风险是本机可以上网，这一点在报告里如实披露，同时由钩子拦截。

## 7. 运行方式

- **断点续跑**：每个阶段写 `.done` 标记，可以重跑；恢复时先读 `PROGRESS.md`。额度用完时，可以靠桌面版 auto-continue 自动续跑，也可以让同学按 `HANDOFF.md` 接力（每人用自己的 FIRMS key）。

- **需要你做的事**：
  1. 选目录；
  2. 执行一次 `gh auth login --web`；
  3. 打开 auto-continue，并设好权限模式。

## 10. 接力设计（额度用完时交给队友）

- **代码和文档**：全部在 GitHub。
- **数据**：几十 GB，不进 git。每个阶段结束时把**处理后的数据**（Parquet，约 1–2 GB）上传为 GitHub Release 附件，并记录 SHA256。队友可以直接下载，也可以用 `python pipeline.py all` 从头重建，原始数据由哈希锁定版本。
- **环境**：`uv sync` 加锁文件；代码统一使用 pathlib，不写 PowerShell 专用脚本，所以 Mac 和 Linux 也能跑，CI 在 Linux 上验证这一点；LightGBM 开启确定性模式并固定种子，保证换机器结果一致。

- **`HANDOFF.md`** 写清楚：装环境 → 填 key → 下载 Release 数据 → 读 PROGRESS → 把下一张任务卡交给 Claude（附一句可以直接复制的提示词）。

| `AGENTS.md` | AI（Codex、Cursor 等通用约定） | 项目规则全集：红线（禁用特征、测试集隔离、不准改评估文件）；开工流程（读进度 → 认领 → 预检 → 按任务卡执行 → 推送）；环境预检清单；遇到不确定的事怎么办 |
| `CLAUDE.md` | AI（Claude Code） | 一行 `@AGENTS.md` 引用，另加 Claude 专有说明（例如钩子） |
| `PROGRESS.md` | 人和 AI | 开头是机器可读的状态块：当前任务卡、状态（ready/in_progress/blocked）、认领人和认领时间、最后推送的阶段、下一步、需要人做的事；下面是阶段表（状态、完成时间、关键数字、commit）和交接备注 |
| `docs/sessions/N-*.md` | AI | 自包含的任务卡：前置条件（哪些阶段已完成、需要哪个 Release 数据包）；**只读计划的哪几节**；要做哪些阶段；验收标准；禁止事项；结束时要更新什么；下一张卡是哪张 |

### 11.2 通用接力提示词（任何时候都用同一段，AI 自己判断进度）

中文版：
```
你在接力一个进行中的数据分析项目（MODIS×VIIRS 火点协调）。请严格按仓库规则做，不要自由发挥。
1. 先读 AGENTS.md 和 PROGRESS.md，用大白话告诉我：项目做到哪一步了、下一张任务卡是哪张、我需要准备什么。
2. 看 PROGRESS.md 的认领信息：如果别人在 12 小时内认领了同一张卡，立刻停下告诉我；否则把认领人写成"【我的名字】"并写上当前时间，然后 commit 并 push。
3. 按 AGENTS.md 的清单做环境预检。需要我本人做的事（申请 FIRMS key、登录 GitHub、安装软件需要授权），停下来一步一步教我做。
4. 执行任务卡，只读任务卡指定的计划章节。每完成一个阶段：跑测试 → 更新 PROGRESS.md → commit → push。
5. 任务卡没有覆盖到的决定，写进 docs/decisions/，并在 PROGRESS.md 里标成"待人确认"。不要擅自改变方法、数据切分或评估规则。
6. 快没额度或要中断时，先把已完成的部分 push，再在 PROGRESS.md 里写清楚"做到哪里了、下一步做什么"。
```
英文版内容相同，放在 HANDOFF.md 里，供不读中文的队友使用。

**指定任务卡的一行版**（用于重做或指定某个阶段）：`按 AGENTS.md 的规则，执行 docs/sessions/3-model.md。`

### 11.3 防撞车和防跑偏

- **认领锁**：PROGRESS.md 的认领信息先 push 的人生效。push 被拒时，先 pull，看到别人已认领就停下。
- **断点**：所有阶段都可以重跑；PROGRESS 里标着 in_progress 的阶段，由接手的 AI 先核对，再决定是续跑还是重做。
- **质量闸门**：每次 push 都要 CI 通过；每张任务卡都有验收标准；最终测试由 GitHub 阅卷，只能考一次，谁接力都一样。
- **护栏放在 CI 上，与用什么 AI 工具无关**：每次 push 都由 CI 检查四件事：
  - 冻结文件（prepare、evaluate、grader、settings、留出区）的哈希没有变；
  - 特征列表里没有年份、地区名或 VIIRS 列；
  - 配置和代码中没有请求 2012/2013 年 VIIRS 的下载；
  - 扫描不到密钥。

  违规的提交会变红，无法合并。Claude 的钩子只是更早的一道提醒。所以不管接力用 Claude Code 还是 Codex，规则执行的严格程度都一样。Codex 需要允许联网和执行命令，AGENTS.md 里会写明。

### 11.4 演练（S00 的验收标准之一）

S00 完成后，我开一个**全新的会话**，只给它通用接力提示词，并要求它"只汇报，不执行"。检查它能否正确说出：当前进度、下一张卡、需要人准备什么。说不对，就修改 AGENTS.md、PROGRESS.md 或任务卡，直到它能说对。
